## 用户真正需要做什么

1. 在桌面和窄屏实际操作面板，检查测试记忆、语言、键盘导航和交接简报的复制/下载。
2. 记录是否适合自己的工作流程，以及具体阻塞问题。
   [清单](USER_SETUP_CHECKLIST.zh-CN.md) 仍保留新部署的复现步骤，本次已完成的原生检查无需重做。

维护者保留的预览使用 `127.0.0.1:18010`；标准新部署使用 `127.0.0.1:8000`。
预览和私有凭据属于本机验收环境，不是公开托管 demo。

## 维护者发布前检查

- 记录最终 commit，核对该 head 的 CI。按 [CONTRIBUTING.zh-CN.md](../CONTRIBUTING.zh-CN.md)
  完成仓库检查，确认 PostgreSQL 与 Docker 任务确实运行，不把被跳过的可选测试算作覆盖。
  隔离部署验证命令为 `python scripts/verify_deployment.py`。
- 修复 P0 失败项，补充人工签收。功能阻塞、越权泄露或数据丢失存在时，对应门槛保持未通过。
- 核对 README、中英文步骤、description、topics、许可、贡献/安全策略与更新记录。
  凭据、用户数据、模型缓存和含密钥的本机报告不能进入源码或构建产物。
- 支持矩阵明确区分模板与实测客户端；发布说明保留 alpha 限制和已知问题。
- 评审通过后再合并和发布，保留证据和 commit 链接。PR 绿灯不等于正式发布；
  当前草稿 PR 需等剩余门槛关闭后再转为可发布状态。

## 已知限制与 alpha 后工作

| 领域 | 当前边界 | 是否阻塞本次 alpha |
|---|---|---|
| 客户端自动化 | 已有工具和增量接口；模板不会调度抓取或自动注入上下文 | 如实说明；完整适配器属于后续工作 |
| 其他工具 | 模板不证明真实对话兼容；已有 Codex/OpenCode 和 Codex/DSH 的有日期实测记录 | 只宣称实际验收过的版本和操作 |
| 工作区与设备密钥 | 已有角色/存储基础，完整成员接入与委派密钥体验尚未完成 | 单 owner 范围下不阻塞，必须写明 |
| 提取器 | 默认正则提取；可选 Ollama 生成待审核事实；OpenAI 提取未实现 | 不阻塞；手动 `memory_add` 无需它 |
| 检索质量 | 已测 BGE-M3 小样本，不保证任意私人语料和所有语言 | 用户确认合成流程，后续扩展评估 |
| 公网托管与规模 | 标准部署绑定本机；多 worker 限流和生产运维仍需进一步设计 | 不宣称已具备公网多租户能力 |
