## 本轮修复

- 同步分页只确认实际扫描的序号，避免直接跳到全局最新序号而漏掉后续页。
  Python/TypeScript 客户端会推进不可见页并及时拉完积压数据。
- 删除记录保留授权标签，避免向其他 scope/项目泄露删除事件；修改和归档
  会通知客户端移除旧记忆。修改保留置顶状态和审批原因。
- 补充 `personal`、`project` 和自动审批审计类型的数据库迁移；修复
  PostgreSQL 默认 JSON 返回值解析，并串行化迁移及同步序号发布。
- 快照支持新记忆类型；使用二进制文件写入，修复 Windows 加密数据损坏；
  文件名增加唯一标识，避免同秒生成冲突；畸形输入返回明确错误。
- Docker 传入稳定密钥，持久保存设置、快照和签名密钥；数据库和模型服务
  仅向本机发布端口。浏览器经过容器转发后使用密钥解锁，不信任伪造转发头。
- 统一 stdio 客户端的数据库、签名密钥和模型地址，避免各工具启动独立临时库。
  新增根目录安装配置和生成随机凭据的启动辅助脚本。
- 模型推理和 embedding 网络请求移出 API 事件循环；临时分类失败不再被永久缓存。
- 客户端加密密钥拒绝路径穿越和覆盖已有密钥；CSRF 校验包含协议、主机和端口。
- CI 新增 Windows/Linux 测试矩阵和真实 Postgres/pgvector 集成任务，锁定
  已验证的核心依赖版本。移除不存在的演示资源链接，修正部署说明和完成度表述。

## 下一次部署验收

1. 运行 `python scripts/setup_local.py`，确认 `.env` 中密钥完整。
2. `docker compose up --build -d`，检查 `docker compose logs api` 和模型健康状态。
3. 打开 `/panel`，必要时用 setup token 解锁，完成一个 client 的 OAuth 授权。
4. 按模板填入相同数据库地址、签名密钥和访问 token，连接两个实际使用的工具。
5. 在工具 A 写入、批准，在工具 B 检索；测试撤销权限、重启持久化和快照恢复。
6. 确认 GitHub CI 中的 Postgres 集成任务通过，再确认真实模型的召回质量。
