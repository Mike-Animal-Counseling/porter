## DSH 桌面 GUI 验收

桌面 profile 已增加私有 Porter MCP 条目，使用该专用标签的只读凭据，保留其他已有插件。
私有一键刷新工具用于更新有效期一小时的 access token；有刷新工具不代表已验证自动续期或
之后每一次桌面会话。已实际执行强制手动刷新：调用 `/oauth/token` 轮换专用读取凭据，仅更新
自己标记范围内的桌面 MCP 配置块，其他插件保持等价。使用刷新后的 token，HTTP 读取、写入
403 拒绝、`work` 空结果、快照哈希与写入端 HTTP MCP 探测均通过。刷新后没有发送第二次 GUI
会话，因此不代表续期后的 GUI 检索已验证。

GUI 自动输入无法发送提示词，因此由用户在桌面新会话中手工发送合成查询，没有提供预期记忆 ID。
随后从桌面控件树独立读到匹配的 ID 和虚构内容，用户也回贴了结果。

更关键的是，直接检查 SQL 审计发现，该专用 GUI 读取客户端只有一条 MCP 读取：

```json
{
  "created_at": "2026-10-27T08:19:55.402947+00:00",
  "action": "read",
  "memory_ids": ["ce54bd24-9c47-49fd-a1a6-ba4ac2409226"],
  "meta": {
    "via": "mcp",
    "hits": 1,
    "tool": "memory_search",
    "top_k": 5,
    "wiki_boost": false
  }
}
```

此前没有使用该读取凭据进行其他 MCP 调用；早先的凭据检查使用 HTTP REST，HTTP MCP 读取
则使用独立写入凭据。因此可区分 GUI 实际执行与配置探测。桌面结果另显示 score `0.4492` 与
`untrusted_data: true`，它们属于客户端观察到的响应字段，不是 SQL 审计独立验证的字段。

实际 GUI 提示词中的 tags 为 `["gui_c1e5fc45dc31", "project"]`，与最初建议的完整
`project:porter-gui-c1e5fc45dc31` 标签不同。服务端将请求标签与凭据允许标签取交集，只留下专用
合成标签。**本次证明了 GUI 的受限标签检索，没有验证完整项目标签的过滤场景。**
模型声称 Porter 将 `project` 重写成 `project:<name>`，这个解释不正确：`apply_tag_filter`
只取交集。返回记录的正规化项目标签来自写入端原先的 `project` 参数，没有为此修改或修复查询逻辑。

本次 GUI 验收证明一次显式 `memory_search`，不代表自动抓取、自动 token 续期或 GUI 凭据
撤销均通过；撤销已在此前单独的内置 CLI 验收中验证。
