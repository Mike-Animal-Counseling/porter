# Porter 实施交接

[English](PLAN.md)

目标是在真实 Codex 和 Claude Code 中双向接力。一个 Agent 留下已验证结论、证据和下一步，另一个 Agent 在新会话首轮读到它。纠正或撤销后，下一次检索立即反映变化。

起点：PR #14 已交付按项目授权、自动提取、审核和回填的预览版。该阶段验证的是合成 Hook 事件与本地 MCP 链路。开工先核对当前默认分支、已有改动与项目说明，避免重复实现。

## 实施顺序

1. **原生接入。** 复用现有 Hook、MCP、OAuth 和审核收件箱。实现连接、诊断与断开，保留用户已有 Hook，按项目独立选择采集与回填。短期令牌续期，长期凭据使用系统凭据存储。Hook 调用有明确超时，服务离线时继续对话。用隔离配置和合成仓库跑两款原生客户端的双向 E2E，覆盖 Windows、Linux、到期、暂停、卸载和超时。记清哪些平台与客户端实际测过。
2. **事实和回填。** Postgres 保持为事实、权限和当前版本的权威来源。区分已验证事实、待验证假设和下一步，保留来源、项目、版本、生效时间和记录时间。按事件键幂等，批准与 outbox 同事务，后台提取和索引可重试。检索先做范围、时态与撤销校验，再做文本与向量排序。回填可追溯到文件、提交或验证结果。已撤销或过期的当前态事实不能被重新注入。
3. **图谱与旧 Wiki。** 用 Graphiti 对已批准事实建可重建的影子索引。FalkorDB Lite 是嵌入式候选，先验证平台、并发、备份恢复，必要时用可选 FalkorDB Compose profile。Graphiti 的 Kuzu 驱动已弃用。图谱候选返回前重新查 Postgres 权限和版本。只有关系或时态题有收益且普通召回、延迟和成本达标才灰度启用。保留旧 Wiki 调用兼容和 Postgres 回退，派生索引可从权威记录重建。

## 验收与发布

- 原生用例把结论从 Codex 带到 Claude Code，再反向跑一次。验证跨项目隔离、证据定位、纠正、撤销和服务不可用时继续对话。
- 同一组任务对测当前版、升级版与 Memmy，记录接入耗时、首轮续接率、手动补充次数、Recall@5、过期命中、回填 p95 和费用。建议目标为 Recall@5 不低于基线、过期命中相对减少至少 50%、抽检 50 条的提取精确率至少 90%。在记录负载的前提下，回填 p95 目标 1 秒以内，保留 1.5 秒超时预算。
- 用隔离项目灰度，演练队列积压、索引重试、恢复和关闭图谱。出现越权或错误事实持续回填时，关闭自动回填或图谱开关。发布实际验证过的兼容矩阵、测试结果和回滚说明。
- 第一批从原生接力与诊断入手。按可独立验收的批次提交，遵循仓库惯例和用户的公开发布检查。
