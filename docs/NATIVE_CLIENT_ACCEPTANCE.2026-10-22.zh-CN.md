## 持久化与撤销对照

本机两个 API 容器均使用原有卷重建，健康检查返回 200，并保留回滚容器。
重建后，一次性 OpenCode C 在全新对话中完成原生搜索，仍取得同一个项目 ID。

随后只撤销 C 的凭据。该 access token 距离过期仍超过 300 秒，因此拒绝并非过期造成：

1. 真实 REST 请求在 **0.14 秒内收到 401 / `token_revoked`**。
2. 使用 C 的全新原生 OpenCode 进程在 MCP 连接阶段收到 HTTP 401 与 `token_revoked`。
   工具目录未加载，**没有产生工具调用或记忆结果**。这是传输层拒绝，不是一次已完成的 `memory_search` 返回。
3. 原始 Codex A 随后完成 `memory_search`，取得相同项目 ID；原始 OpenCode B 的另一场全新对话也完成相同检索。

原始 A/B 的配置和凭据保持可用。这些对照证明：撤销一次性凭据只阻断该凭据，
不会连带停用其他客户端；API 重建后，选定的原生调用流程仍然可用。

## 验收过程中发现并修复的问题

第一次原生 Codex 保存碰到 BGE-M3 冷启动请求超时；随后单独调用 `/embed` 预热，
在 1.0 秒内返回 1024 维向量，再次原生保存成功。修复改善了失败提示，不会消除冷启动延迟。

HTTP 向量服务的失败此前可能冒出为通用错误。后续修复将超时转换为安全的 **504** Porter 错误，
连接失败、上游 HTTP 错误和无效 JSON 转换为安全的 **503** Porter 错误。
保留原有超时设置，**没有新增自动重试**。针对性检查记录为 **40 项通过**，其中包括 22 项新增向量服务用例。

此前全量 650 项通过及其 CI 属于较早的检查基线，不是本次修复的新全量结果。
